Limits come only after a session's first reply, so the card keeps the last known values greyed with their timestamp rather than going blank.

Data source

Claude Code's status-line JSON, sent to a script on every update. It carries context used %, cost, and for Pro and Max logins the 5-hour and 7-day used_percentage and resets_at.

How it gets in

Coucou installs a status-line relay the way it installs hooks, with a diff you confirm: a wrapper that forwards the JSON to Coucou's socket and then runs Orca's existing status-line script unchanged. Orca's status bar keeps working.

Caveats

Rate-limit fields exist only for claude.ai Pro and Max. On an API-key login the card shows context and cost only. Cost is the session's own figure, not a billing total.

Claude numbers

From Claude Code's status-line JSON. Coucou installs a relay that forwards the JSON to its socket, then hands it to Orca's existing status-line script unchanged, so Orca's own status bar keeps working. You confirm the settings diff, as with hooks. Pro and Max logins only for the limits; context and cost always.

GLM numbers

Polled every minute from Z.ai's quota endpoint with your coding-plan key: 5-hour and weekly percentage, remaining, reset time and plan level. Verified today with the key pi already uses. Zero tokens consumed. Settings gets a "Z.ai (GLM)" box with an "Import from pi" button so you never paste the key.

Caveats
  • Orca manages the status-line entry and may rewrite it on its updates. Coucou's Settings will show the relay as missing if that happens, with a one-click reinstall.
  • Claude limits appear only after a session's first reply. Until then the card keeps the last known values greyed with a timestamp.
  • The Z.ai endpoint is what their dashboard uses, not a documented API. If it changes, the GLM group shows "unavailable" and nothing else breaks.

Orca orchestration board

Coordinator-side view: every task in the current run with its state, polled from the Orca CLI.

not recommendedmedium · app, needs a handle

A run with three tasks

01 tooling done 10m 02 chat implementing 03 usage PLAN?

Looks useful, but the information already arrives from inside each worker through the pi extension, and the only new thing, the PLAN question, is answered by Claude in seconds anyway.

Why not
  • Task titles, states and gates need a bound coordinator terminal handle. A menu-bar app would have to own an Orca terminal for life.
  • Run and dispatch lists without a handle give IDs only, as checked today.
  • It duplicates option C's pills with a lag.
If you still want it

Cheapest honest version: tag each pi pill with its Orca task id, parsed from the preamble Orca pastes into the worker. Zero polling, five lines in the extension.
