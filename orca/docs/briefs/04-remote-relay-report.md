## Deviations

1. **`RelayServer.swift`: `TimeoutBox` wrapper around the bridge timeout `DispatchWorkItem`.**
   Appendix F verbatim does not compile under Swift 6 `-strict-concurrency=complete`:
   `RelayServer.swift:233:43: error: capture of 'timeout' with non-Sendable type
   'DispatchWorkItem' in a '@Sendable' closure` (the `NWConnection.send(completion:)`
   completion closures that call `timeout.cancel()` are `@Sendable`). Smallest fix that
   satisfies the compiler, per the brief's rule: added a 4-line
   `private final class TimeoutBox: @unchecked Sendable { let work: DispatchWorkItem; … }`
   next to `Flag`, wrapped the work item (`let timeoutBox = TimeoutBox(timeout)`), and the
   three `timeout.cancel()` calls inside `@Sendable` closures became `timeoutBox.work.cancel()`.
   Behaviour, timeouts, status codes, auth and the socket protocol are unchanged; the timer
   is still cancelled on completion exactly as designed.
2. **`HookServer.swift` host-tag edit applied by scripted exact-match, not the edit tool.**
   The two `projectName` lines in `processEvent` and `processPermissionRequest` are
   character-identical, so a unique-anchor text edit is impossible. A script asserted the
   anchor line occurs exactly twice, then replaced both occurrences with the D3 block
   (`let` → `var` + `remote_host` tag). Content is exactly the D3 change; only the mechanism
   differs. (The allow-list edit used the normal edit tool.)

## Behaviour checklist (D6, from code)

- Listener on all interfaces, configured TCP port, only while enabled; bind failure logs
  `Relay: cannot listen on <port>` and returns without touching app state.
- Every request requires `Authorization: Bearer <token>`, else `401` + log line.
- `GET /health` → `200 {"ok":true,"app":"coucou"}`.
- `POST /hook` → body validated as a JSON object, written to `HookServer.socketPath` as one
  `\n`-terminated line, socket reply line returned as the `200` body; socket unreachable →
  `502`; 122 s bridge timeout → `504` with `{"permissionDecision":"ask",…}` fallback.
- Limits: 1 MB body, 64 KB headers, 15 s request timeout, 32 concurrent connections.
- Logs once on start (`Relay listening on port N`) and per rejected request; none per
  successful event.
