00

Why a patched build, not the zip

Two separate problems: the published binary, and a hard-coded VS Code filter.

The binary. The v0.1.0 zip on the Releases page is ad-hoc signed with no Team ID, not notarized, has a broken seal from stray ._ files, and was built on the author's laptop with no CI provenance. It also predates the socket-permission and logging fixes already on main.

The filter. Upstream Coucou drops every Claude Code event unless the session's TERM_PROGRAM or bundle id contains "vscode". Orca panes report TERM_PROGRAM=Orca and bundle com.stablyai.orca. Unpatched, Coucou would show nothing for any of your sessions and log each event as ignored.

BehaviourZip v0.1.0main, unpatchedmain + Orca patch

Socket 0600, logs without commandsnoyesyes
Orca sessions appear in the notchignoredignoredyes

Click pill → focusesVS CodeVS CodeOrca

The patch touches eight files. It replaces the two VS Code checks with a small allowlist that includes Orca, makes the Claude pill and the idle card's button focus Orca, renames the idle slot to "Orca · Claude Code host", shows hooks status on that card, starts with no service pills, and adds a Claude Code chat provider that runs the local claude -p with your existing login, made the default. The diff summary is in step 02.

01

Prerequisites

This Mac has only the Command Line Tools today. Full Xcode is required.

The project is generated by XcodeGen and built with xcodebuild, which the Command Line Tools don't include. Checked on 2026-10-02: the active developer directory is /Library/Developer/CommandLineTools and xcodegen is not installed.

  1. Install Xcode from the Mac App Store. It's a multi-gigabyte download. Open it once afterwards so it finishes installing its components.
  2. Point the command-line tools at it and accept the license.
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
xcodebuild -version        # want: Xcode 16 or later
brew install xcodegen
Python 3 is already present. The hook relay Coucou installs is a Python script run with /usr/bin/python3, which the Command Line Tools provide. No extra install.

  -project NotchBuddy.xcodeproj \
  -scheme NotchBuddy \

  CODE_SIGNING_REQUIRED=NO

04

Sign and install

Ad-hoc sign it yourself and copy it into Applications.

An ad-hoc signature is enough for an app you built on the machine that runs it. The file never carries a quarantine flag, so Gatekeeper won't show the "unverified developer" dialog the README warns about.

APP=~/src/coucou/NotchBuddy/build/Build/Products/Release/Coucou.app
codesign --force --deep --sign - "$APP"
rm -rf /Applications/Coucou.app
ditto "$APP" /Applications/Coucou.app

07

Install the Claude Code hooks

Orca already owns 13 hook events in your settings. Coucou adds 12 alongside them without conflict.

Checked on this Mac: every existing hook in ~/.claude/settings.json is Orca's relay. Its PermissionRequest hook prints an empty object and only notifies Orca. It never returns an allow or deny. So Coucou is the only hook that will ever answer a permission request, and only when you click a button in the notch.

Take your own backup, then install from the app.

cp ~/.claude/settings.json ~/.claude/settings.json.pre-coucou

Menu-bar icon → Settings… → Claude Code → Install hooks. Read the diff before confirming. You should see:

  • One new entry appended under 12 events: SessionStart, SessionEnd, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, Notification, Stop, StopFailure, SubagentStart, SubagentStop.
  • Each pointing at ~/Library/Application Support/NotchBuddy/nb-hook, 10 s timeout, except PermissionRequest at 120 s.
  • Orca's entries untouched, including TeammateIdle and PostCompact, which Coucou doesn't register.
  • Keys reordered alphabetically. Cosmetic. The file is re-serialised rather than patched.

After confirming, make sure the file still parses and the counts match.

python3 - <<'EOF'
import json, os
d = json.load(open(os.path.expanduser('~/.claude/settings.json')))
for k, v in sorted(d['hooks'].items()):
    print(f'{k:22} {len(v)}')
EOF
Expect11 events at 2, Notification at 1, TeammateIdle and PostCompact at 1. A parse error or any 0 means restore the backup. Restorecp ~/.claude/settings.json.pre-coucou ~/.claude/settings.json

Now start a Claude Code session in an Orca pane. The Claude pill should animate on the first tool call. If nothing moves, check the log for ignored events:

grep -c Ignored ~/Library/Logs/NotchBuddy/nb.log
# want: 0. A nonzero count with "from Orca" means the unpatched filter is running.
08

Install the pi extension

One file in pi's extensions folder. Every pi process loads it, including the glm-5.3 workers Orca dispatches.

pi fires none of Claude Code's hooks, but it has an extension system, and Orca already uses it: ~/.pi/agent/extensions holds Orca's own status extension. The file at coucou-orca/pi/coucou-status.ts goes next to it and relays pi's events to Coucou's socket, tagged so Coucou gives each worker its own pill.

cp ~/Workspaces/Code/coucou-orca/pi/coucou-status.ts ~/.pi/agent/extensions/coucou-status.ts

No restart of anything is needed. pi loads extensions at process start, so the next pi you or Orca launch picks it up. Verify with a one-word run from a scratch folder while Coucou is open:

cd /tmp && pi --no-session --model zai/glm-5.3 -p "Reply with exactly one word: pong"
ExpectA pill named pi-tmp appears, animates while the request runs, shows a finished card with "pong", and retires about five seconds later. Nothing?Check Coucou is running and ls -l ~/Library/Application\ Support/NotchBuddy/nb.sock exists. The extension never prints, and never blocks pi, so a missing socket is silent by design.

How a dispatched worker looks. The coordinator skill has Orca paste "Read docs/briefs/NN-slug.md in full and execute it" into the pane. The extension reads the brief name from that first prompt and tags the pill pi-NN-slug, so three parallel workers are three pills. Then, from the worker's own tool calls, it surfaces the protocol's milestones as steps:

Worker doesPill shows
Reads the brief, edits files, runs testsRead · 07-auth-hooks.md, Edit · hooks.ts, Bash · npm test, with a failed-step marker on non-zero exits
orca orchestration send --type heartbeat --phase implementingphase · implementing
orca orchestration send --type status --subject "all files on disk"note · all files on disk
Writes docs/briefs/07-auth-hooks-report.mdreport written · 07-auth-hooks-report.md
orca orchestration worker-done --outcome succeededFinished card: worker_done · succeeded. Mochi jumps, the pill retires
pi asks to approve a toolPill switches to the question state. Approve in the pane as before
Provider error, for example a timed-out requestError card with the provider's message, once, even though pi retries

Interactive pi sessions without a brief get a pill named after the working directory, or after the session name when you pass --name. Force a tag with COUCOU_AGENT=my-tag, or silence one process with COUCOU_DISABLE=1. Tags are lowercase letters, digits and hyphens, at most 24 characters, which is what Coucou accepts.

Tested on this Mac on 2026-10-02 with pi 0.87.1 and glm-5.3: tool events, the final message, event ordering, and the error path with an unreachable provider. The full dispatch sequence was exercised against a simulated socket since no worker was running at the time. Nothing in the extension leaves the machine; it writes only to Coucou's owner-only socket.
09

Operating rules

Keep the convenience, keep the oversight.

Approve Bash from the notch, nothing else

The card shows the full command for Bash. For Edit, Write and every other tool it shows only the tool name. Approve those in the Orca pane where you can see the path and diff.

Treat "Always" as a settings change

It writes a permanent permission rule into your Claude settings, exactly like "always allow" in the terminal. Use "Allow" unless you would write that rule by hand.

One card at a time

If two Orca panes request permission together, the newer request takes the card and the older one is handed back to its terminal to re-ask. Nothing is auto-approved.

Workers are their own pills

Each pi worker shows as pi-NN-slug with its phase, notes and report as steps. Claude Code's own SubagentStart and SubagentStop events still animate the Claude pill. Watch the tree too: files landing is still the best progress signal.

Hooks never block Claude

If Coucou isn't running, the relay exits in under a second with no output. Quit the app any time without breaking a session.

Chat is your Claude Code

Each message runs the local claude CLI headless with WebSearch, WebFetch and Read allowed, resuming the same session for follow-ups. Dropped files are read by the CLI from disk. No key leaves the machine because there is none.

Updating

Rebase the orca branch, read the hook server diff, rebuild.

cd ~/src/coucou
git fetch origin
git log --oneline HEAD..origin/main -- NotchBuddy/Sources/App/HookServer.swift
git rebase origin/main
ConflictOnly happens if upstream touches the two VS Code checks or the Claude pill handler. Re-apply the same three edits and git rebase --continue. Upstream fixIf a future upstream release accepts other terminals natively, drop the branch and build main instead.

Then repeat steps 03 to 05, quitting Coucou before copying over the app.

cd ~/src/coucou/NotchBuddy && xcodegen
xcodebuild -project NotchBuddy.xcodeproj -scheme NotchBuddy \
  -configuration Release -derivedDataPath build build \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO
osascript -e 'quit app "Coucou"'
codesign --force --deep --sign - build/Build/Products/Release/Coucou.app
rm -rf /Applications/Coucou.app
ditto build/Build/Products/Release/Coucou.app /Applications/Coucou.app
open /Applications/Coucou.app

If the relay script changed upstream, open Settings and click Install hooks again. The app rewrites nb-hook and shows a settings diff, which should be empty.

11

Rollback

Four moves. No Keychain cleanup needed since no keys were entered.

  1. Remove the hooks. Settings → Claude Code → Remove hooks, or restore your pre-install copy. Orca's hooks are unaffected either way. 
    cp ~/.claude/settings.json.pre-coucou ~/.claude/settings.json
  2. Remove the pi extension. Running pi processes keep it until they exit. 
    rm -f ~/.pi/agent/extensions/coucou-status.ts
  3. Quit and delete the app and its data. 
    osascript -e 'quit app "Coucou"'
rm -rf /Applications/Coucou.app \
  ~/Library/Application\ Support/NotchBuddy \
  ~/Library/Logs/NotchBuddy \
  ~/Library/Preferences/fr.louisraille.NotchBuddy.plist
rm -f ~/.claude/settings.json.bak-*   # Coucou's own backups, optional
  4. Revoke the one permission. System Settings → Privacy & Security → Automation. Remove Coucou's entry for Orca.
